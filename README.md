## 项目背景

小米手环 11（NFC 版，model `miwear.watch.q66nfc`）的数据获取有三条技术路径，本项目对三者做了完整的工程验证（详见 [docs/协议逆向笔记.md](docs/协议逆向笔记.md)）：

| 路径 | 结论 |
|---|---|
| PC 蓝牙直连（标准 GATT） | 仅**实时心率**可读（0x180d），完整数据被私有 L2CAP CoC 加密通道拦截 |
| HCI 协议深度逆向 | 帧结构已还原（47 种消息类型），但认证/数据在加密通道内，解码成本极高 |
| **小米云端健康 API** | ✅ **本项目采用**：步数/睡眠/心率/血氧/压力/卡路里/运动记录**全部可得** |

因此项目基于小米官方健康云接口（`hlth.io.mi.com`）实现完整数据读取，并封装为易用的本地看板与免安装客户端。

## 功能特性

- **登录即用**：任意小米账号密码登录；首次登录后会话持久化，重启自动恢复，退出登录清除
- **7 类健康指标**：步数 / 距离 / 卡路里 / 站立 / 睡眠（评分、深睡浅睡、分段）/ 心率（日均、静息、区间）/ 血氧 / 压力 / 运动强度
- **逐点明细**：心率 / 血氧 / 压力约 10 分钟间隔的逐点曲线（近 3 天，同屏对比）
- **运动记录**：骑行 / 跑步等（距离、时长、平均心率）
- **自定义导出**：每日汇总 + 逐点明细 + 运动记录，CSV 或 JSON，多文件自动打包 zip
- **两种形态**：免安装桌面客户端（pywebview 原生窗口）与网页版
- **完全本地化**：全部 Python 依赖（vendor/）与 ECharts 图表库本地携带，离线可跑；打包客户端为单文件 exe
- **版本管理**：构建脚本自动递增版本号、记录 SHA256 与变更日志

## 快速开始

### 形态一：免安装客户端（推荐）

1. 构建或下载 `MiBandHealth_vX.Y.Z.exe`（见 [构建](#版本管理与构建)）
2. 双击运行：
   - **环境自检**：端口占用自动切换、小米服务器可达性检测
   - **登录状态检查**：读取 exe 旁 `session.json`，有效则直接进入看板（免输入）
   - 弹出**原生桌面窗口**（关闭窗口即退出程序）
3. 数据目录（exe 旁自动创建）：`数据/session.json`、`数据/导出/`、`数据/logs/startup.log`

### 形态二：网页版

```bash
# Windows：双击 启动看板.bat；或命令行
python app.py
# macOS / Linux
python3 app.py
```

浏览器自动打开 `http://127.0.0.1:8000`。首次输入小米账号（手机号）与密码登录，之后免密直达看板。

> 依赖已打包在 `vendor/`（源码运行时）或 exe 内（客户端），**无需联网安装依赖**；仅登录与拉取数据需联网。

## 版本管理与构建

```bash
# 构建环境（已装 pywebview + pyinstaller 的 Python 3.10+ 虚拟环境）
python build.py                 # patch 递增：1.0.1 -> 1.0.2
python build.py --bump minor    # minor：1.0.1 -> 1.1.0
python build.py --bump major    # major：1.1.0 -> 2.0.0
python build.py --no-bump --changes "说明"   # 用当前版本重新构建
```

每次构建自动完成：

1. 读取并**递增版本号**，写回 `app.py` 的 `APP_VERSION`
2. PyInstaller 打包为**单文件 exe**（内嵌 index.html / echarts.min.js / 全部依赖）
3. 产物命名 `MiBandHealth_vX.Y.Z.exe`，计算 **SHA256**
4. 更新 `客户端构建/versions.json`（版本 / 日期 / 变更 / SHA256 / 大小）与 `CHANGELOG.md`

更迭方式：新 exe 直接替换旧版；`数据/` 目录保留，登录态与导出数据不丢失。

Windows 用户可直接双击 `构建客户端.bat`。

## 数据接口说明

数据来源为小米健康云 `hlth.io.mi.com`，登录与签名协议为小米私有（`mi_crypto`：nonce + AES/Base64 加密参数），详见 [docs/数据接口说明.md](docs/数据接口说明.md)（含字段字典与脱敏示例数据）。

核心接口一览：

| 接口 | 用途 |
|---|---|
| `/app/v1/source/get_source_list` | 获取绑定设备列表 |
| `/app/v1/data/get_aggregated_fitness_data_by_time` | 按天聚合数据（steps/sleep/heart_rate/spo2/calories/intensity/valid_stand） |
| `/app/v1/data/get_fitness_data_by_time` | 逐点明细（heart_rate/spo2/stress） |
| `/app/v1/data/get_sport_records_by_watermark` | 运动记录（watermark 分页） |

## BLE 直连可行性结论

详细逆向过程见 [docs/协议逆向笔记.md](docs/协议逆向笔记.md)，核心结论：

- 手环 11 的 App↔手环通信**不走标准 ATT/GATT 特征通道**，数据与认证走 **L2CAP 动态 CID 私有通道（CoC）**
- Windows BLE 客户端（WinRT / bleak）**不支持 L2CAP CoC**，PC 无法建立数据通道
- 认证协议在加密通道内，无法通过抓包学习
- **PC 标准 GATT 可用的**：实时心率（0x180d）、电池（0x180f）

## 项目结构

```
.
├── app.py            # 后端服务 + 客户端启动（登录/数据代理/导出/环境自检/桌面窗口）
├── index.html        # 前端页面（苹果设计风格，ECharts 图表）
├── echarts.min.js    # ECharts 5.5.1（本地化，可自行下载，缺失时自动回退 CDN）
├── build.py          # 版本管理构建脚本
├── 构建客户端.bat     # Windows 一键构建
├── 启动看板.bat       # Windows 网页版一键启动
├── vendor/           # （运行时生成说明）本地化 Python 依赖
├── 客户端构建/        # （构建产物）exe + versions.json + CHANGELOG.md
├── 数据/             # （运行时生成）session.json / 导出 / logs
└── docs/
    ├── 数据接口说明.md  # 云端 API 与字段字典（脱敏）
    └── 协议逆向笔记.md  # BLE 私有协议逆向结论（脱敏）
```

> 说明：`echarts.min.js`（约 1MB）未纳入仓库，请自行下载 ECharts 5.5.1 的 `echarts.min.js` 放于项目根目录；页面已在本地缺失时自动回退到 jsDelivr CDN，源码模式可直接运行。

## 安全说明

- 服务只监听 `127.0.0.1`（仅本机可访问），不开放局域网
- 密码仅保存在程序内存中用于本次登录，**不写入任何文件**
- `session.json` 仅含会话令牌（等同登录态），退出登录即删除；会话令牌约 30 天过期需重新登录
- 数据直连小米官方接口，**不经过任何第三方**
